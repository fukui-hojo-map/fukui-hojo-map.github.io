# ふくい圃場マップ — 事前計算＋静的配信

県内の圃場（筆ポリゴン）ごとの NDVI を **週1回まとめて計算** し、結果を **静的ファイル** として公開する仕組みです。
利用者（農家・普及員）はブラウザで地図を開き、圃場をタップするだけ。利用時に計算は発生しないため、
サーバー費用はほぼゼロで、利用者が増えても遅くなりません。

```
 筆ポリゴン(農水省)  Sentinel-2(Copernicus)
        │                  │
        ▼                  ▼
  build_cells.py     update_ndvi.py  ← Google Earth Engine で区画平均を計算
  (区画をグリッドに分割)  (未計算の観測日だけ追記)
                     trend.py        ← 過去の年の作物の見分けと田の中の差（生育傾向マップ）
                     vigor.py        ← 例年の育ち（生育傾向マップの田ごとの値。Earth Engine は使わない）
        │                  │
        └──────┬───────────┘
               ▼
       site/data/           ← GitHub Actions が週1回更新し、GitHub Pages で配信
        ├ index.json          （セル一覧・更新日）
        └ cells/<id>/
           ├ parcels.geojson  （区画の形（約1m単位に丸め）・有効画素の期待数）
           ├ inner.geojson    （計算用: 畦畔を避けて5m内側に縮めた形）
           ├ px_<年>.png/json （圃場内マップ: 晴れた日の10m画素のNDVI）
           ├ trend.png/json   （生育傾向マップ: 年ごとの作物の手がかりと、6月ごろ・8月ごろの田の中の差）
           ├ vig.json         （生育傾向マップ: 稲の年ごとの頭打ち・近くの同じ作期の田との差と、田の値。県全体の分布は data/vig_stats.json）
           ├ hist.json        （ndvi.json より前の年の 5/10〜9/30 の区画平均。形式は ndvi.json と同じ。稲の見分け・例年の育ち用）
           ├ spring.json / pre.json / post.json （ndvi.json より前の年の 4/15〜6/10・3/1〜4/14・10〜11月。稲の見分け用）
           ├ radar.json / hist_ls.json （ndvi.json より前の年のレーダー VH 4/15〜8/10・Landsat 4/15〜9/30。稲の見分け用）
           ├ crop_s.json      （作物の見分け: 田・年ごとに 稲/麦/休/他・稲らしさ%・暫定・理由。pipeline/crop.py が作る）
           └ ndvi.json        （観測日 × 区画の NDVI と有効画素率。50%未満の観測は保存しない）
               │
               ▼
       site/index.html      ← 表示範囲のセルだけ読み込む地図ビューア
```

## できること（ビューア）
- 航空写真の上に区画。選んだ日付の NDVI で色分け（地域全体の生育の見え方）
- 区画をタップで最大10枚を比較。今年（5/10〜9/30）／前年との重ね
- 近隣の田の平均（半径可変）との比較、要約表
- 雲・かすみで一斉に落ちた観測日を自動除外（詳細設定で戻せる）
- ゾーン表示（いつも入）: 田の中の色を段階に分け、境目に線を引いて地力マップのようなゾーンで見せる（10m画素をなめらかにつないでから7段階に分ける。絶対表示は NDVI 0.1 ごと、相対表示は目盛りの ±15%・45%・75%、生育傾向は近くの同じ作期の田との NDVI の差 −0.045・−0.025・−0.01・+0.005・+0.018・+0.03 で区切る）
- 塗り方は選んだ時点で地図全体に反映する: 絶対表示は区画ごとの NDVI、生育傾向マップ・圃場スコアマップは区画ごとの例年の育ち（vig.json の田の値）で塗る。拡大（16以上）すると、選んでいない見えている圃場も田の中まで色分けする（相対表示はこのときだけ。多いときは画面の中心に近い 250 枚まで）。土壌図のときは塗りを薄くし、土壌の色が透けて見えるようにする
- 軽さ: 田の中の色（ゾーン表示）は canvas のまま地図に置き（PNG にしない）、田・塗り方・日付ごとに覚えて描き直さない（選んだ田も）。解像度は長い辺 360px ほど。選べる田は10枚まで。見えている広さが 8km² 以下（パソコンで拡大16・携帯で15くらいから）のときだけ区画・塗り方の欄を出し、見えている範囲（少し広め）のセルの区画だけを地図に置く（離れたセルは外すがデータは残す）。雲・かすみの日の判定は読み足した区画の分だけ足す
- 推移のグラフ（今年・前年と重ねる）は、5/10〜6/15 に初めて水面の値（NDVI 0.05 以下）になった日（代かき・水張り）より前の点を出さない（雑草・土の緑で、稲の育ちではないため）
- 開発者向けの機能（作付計画・圃場スコアマップ・追肥マップ・生育予測）は、このリポジトリには入れていない（非公開）
- 背景の地図は 航空写真・淡色地図・土壌図 の3つから選べる。土壌図は国土交通省 土地分類基本調査（20万分の1）の土壌図を土の種類で色分け
  （data/soil_mlit.geojson。毎回の更新でまだなければ作る）。土壌図のときは圃場は枠だけにする
- 「Excelで保存」: 番号つきの地図（航空写真にいまの色分けと田の形）と、その下に選んだ圃場の一覧（番号・面積・例年の育ち（近くの同じ作期の田との差・目安（よく育つ〜弱い）・年ごとの差）・直近と今年の最大の NDVI・年ごとの作物・緯度経度・地図へのリンク。
  スコアマップのときだけランクと点数の内わけ・説明も）を同じシートに、NDVI の推移（日付 × 田）を別のシートに .xlsx で保存（ExcelJS を押したときだけ読み込む）。
  枚数が多い（13枚以上）ときは地図を別のシートに分ける
- 「この場所のリンクをコピー」で、位置と選択した圃場をそのまま共有
- 塗り方「生育傾向マップ」: **例年（稲の年）よく育つ田は濃く、育ちが弱い田は薄く** 塗る（pipeline/vigor.py → vig.json）。
  稲の年ごとに「その年いちばん茂った時（出穂のころ）の NDVI（6/14〜9/19 の晴れた日の最大）」を、近く（3×3 セル ≒ 7×5.5km）の、
  **同じころに植えて（NDVI が 0.5 を越えた日）同じころに刈った（0.45 未満に落ちた日）田** の平均とくらべる（6日の枠。10枚に足りなければ広げる）。
  品種（早生〜晩生）・田植えの時期・直播の違いはくらべる相手で消える（同じ日の NDVI をくらべると、早く植えた田・早生ほど高く出ていた）。
  小さい田は縁（畦・道）が画素に混ざって低く出るので、区画の内側の面積ごとの差を先に差し引く。田の値＝年ごとの差の平均を、年数に応じて 0 に寄せたもの
  （1〜2年だけの田が極端に出ないように）。2年以上くらべられた田だけ塗る。今年の分は 9/20 から入れる（まだ刈っていない田は、まだの田どうしでくらべる）。
  県全体（2022〜2026年）で、年どうしの一致 0.58、植えた時期との相関 −0.12、熟期との相関 +0.08（今までの 6月ごろ・8月ごろ の値は植えた時期と −0.50）、100m 以内の田どうしの相関 0.49。
  田の中の濃淡は、8月ごろ（7/20〜8/20）の田の中の差（毎年よくくり返す。年どうしの一致 0.72。6月ごろは 0.44）を稲の年で平均し、
  縁からの距離ごとの見かけの下がり（県全体の平均の形）を除いて、田の値に足す。
  グラフは稲の年ごとの「近くの同じ作期の田との差」（点）と例年の値（点線＝地図の色）。要約の表に例年の値・目安（よく育つ〜弱い）・何回中何回 近くの田より良いか。
  いちばん茂った時の NDVI の平均が 0.65 未満の田は「ふつうの稲作でないかも」と添える。地力のほか、作り方（肥料・植え方・品種の茂り方）の差も入る。
  田の中のばらつき・深い所（圃場の評価）は、これまでどおり6月ごろ・8月ごろの「その田の平均との差」から計算する（drawTrend）。
  2年3作で麦・大豆（ソバ）を作った年・休耕の年は、作物の見分け（crop_s.json、下の「作物の見分け」）で除く（稲と麦・大豆では、湿った所の強い・弱いが逆になるため）。
  グラフは、稲の年の 5/10〜9/30 の推移を1日ごとに線でつないで平均したもの（実線）と

## セットアップ（1回だけ）

専門用語なしの手順書は `SETUP_やさしい版.md` を参照。

### 1. Google Earth Engine（計算エンジン）
1. Google Cloud プロジェクトを Earth Engine に登録（非営利・研究用途として登録）
2. Cloud コンソール → IAM → **サービスアカウント** を作成し、JSON 鍵をダウンロード
3. そのサービスアカウントに `Earth Engine Resource Viewer` と `Service Usage Consumer` のロールを付与
4. Cloud コンソールで `Earth Engine API` を有効化（まだなら）

### 2. GitHub リポジトリ
1. このフォルダをそのままリポジトリにする（**Public** にする。無料プランでは Public リポジトリだけが Pages で公開でき、Actions の実行時間も無制限）
2. Settings → Secrets and variables → Actions に3つ登録
   - `EE_SERVICE_ACCOUNT` … サービスアカウントのメールアドレス
   - `EE_PRIVATE_KEY` … JSON 鍵ファイルの中身をそのまま貼る
   - `EE_PROJECT` … Cloud プロジェクトID
3. Settings → Pages → Source を `gh-pages` ブランチにする（初回の Actions 実行後にブランチができます）

### 3. 区画データ
`config.yaml` の `parcel_sources` に筆ポリゴンの入手先を書きます。
- 農林水産省「筆ポリゴンデータ」ページの **福井県 FlatGeobuf（分割ファイル）** の URL を並べる、または
- 筆ポリゴン公開サイト（open.fude.maff.go.jp）から市町ごとに GeoJSON を落として `parcels/` に置く
`bbox` で範囲を絞れます。まずは1つの市町か地区で試すのが安全です。

### 4. 初回実行
Actions → `weekly-ndvi` → **Run workflow**。初回は過去24か月分をさかのぼるので数時間かかります。
1回で終わらなくても、途中まで保存して次回に続きから計算します（`max_minutes` を超えると自動で切り上げ）。
終わったら `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けます。

## 運用
- 5〜9月は毎日、それ以外は毎週月曜の 4:23（JST）に自動更新。手動実行も可
- NDVI を公開したあと、残り時間で生育傾向マップのデータを作り、作物を見分け、例年の育ち（vigor.py、1分ほど）を計算してもう一度公開する。最初は全セルで数日かかる
  （`trend_center` に近いセルから。できた年は作り直さない。毎年9月に入ると、その年の分を足す）
- 筆ポリゴンが年次更新されたら、`config.yaml` を直して **Run workflow の `rebuild_cells` にチェック**
- 1セル ≒ 2.2km×1.85km。県全体で数百セル。週次更新は数分〜数十分
- ログは Actions の実行画面で見られます。1セルの失敗は飛ばして続行します
- **公開の停止**: GitHub で `site/switch.json` を開き、鉛筆ボタンで書き換えて「Commit changes」。1〜2分で反映（switch ワークフロー）
  - `"site": "off"` … サイトを「ただいま公開を停止しています」だけにする（`"on"` で戻す）
  - `"dev": "off"` … 開発者モード（圃場スコアマップ・作付計画）を、開発者の鍵（`?dev=鍵`）で開いた端末も含めてだれにも出さない

## 設定の要点（config.yaml）
| 項目 | 意味 |
|---|---|
| `only_paddy` | 田（land_type=100）だけを対象にする |
| `edge_m` | 畦畔を避けて内側に縮める距離。10m画素なら5mが目安 |
| `history_months` | 初回にさかのぼる月数（前年重ね表示には24） |
| `max_scene_cloud` | シーン雲量がこれ以上の画像は使わない。空欄なら画像全体の雲量では捨てない（区画ごとに判定） |
| `cloud_score_min` | 雲判定 Cloud Score+ の晴れ度（0〜1）。これ以上の画素だけ使う。変えると次回の更新で全期間を計算し直す |
| `landsat` | Landsat 8/9（NASA HLS, 30m）も使う。Sentinel-2 がない日の観測を補う（グラフでは白抜きの点） |
| `landsat_min_pixels` | Landsat の30m画素がこれ未満しか入らない小さい区画には Landsat を使わない |
| `radar` | Sentinel-1 レーダー（雲を通す）も使う。指標は VH の後方散乱（区画の中央値、dB）。地図では範囲ごとに晴れた日の NDVI との関係から推定 NDVI に換算し、5/10〜7/31 の空白を埋める（グラフではひし形の点） |
| `radar_window` | レーダーを計算する時期（月-日、各年） |
| `pixel_maps` | 圃場内マップ（10m画素ごとの NDVI）を作る。地図の「塗り方」で圃場内（絶対・相対）を選ぶと、選んだ圃場の中を色分けする |
| `pixel_window` | 圃場内マップを作る期間（月-日）。今年と昨年の分を作る |
| `trend_maps` | 生育傾向マップを作る。年ごとに、4月の NDVI（麦）・5〜6月のレーダー（水張り）・7月の NDVI（稲の育ち）で作物を見分ける手がかりと、6月ごろ・8月ごろの「晴れた日のその田の中央値との差」を保存し、ビューアで稲の年だけを重ねる |
| `trend_from` | 何年からさかのぼるか（いまは2022年から。Sentinel-2 が日本で安定して使えるのは2019年から） |
| `trend_windows` | 「6月ごろ」「8月ごろ」の期間（月-日） |
| `trend_center` | この場所（経度, 緯度）に近いセルから先に作る |
| `wet_maps` | 機械のハマりやすさの手がかり（土壌図・標高・衛星の乾き）を作る。土・地形は1回だけ（取れなければ28日後にもう一度）。1セル数秒〜数分 |
| `wet_sat` | 衛星の乾き（GEE）も作る。最初は全時期（全セルで数時間。何回かの実行に分けて続きから）、そのあとは新しい時期（春・秋）が終わり ERA5-Land がそろったら、その時期だけ足す。土・地形を全セルで先に作ってから、残りの時間で乾き |
| `wet_seasons` | 最初に取る乾きの時期の数（新しい方から）。一度足した時期は残る |
| `cell_deg_lon/lat` | 配信ファイルの分割単位 |

## 限界
- 10m 画素なので、細長い区画や小さな区画は隣の影響を受けます（有効画素率で絞り込み可）
- 雲・かすみは完全には除けません。自動除外は「多くの区画が一斉に下がって次で戻る日」だけです
- NDVI は 0.8〜0.9 で頭打ちになるため、繁茂した圃場間の差は実際より小さく見えます
- 作物の見分け（`pipeline/crop.py` と `crop_core.py`・`crop_model.json`。毎回の更新の最後に全部の田・年を見分け直す。4コアで4分ほど）:
  - 証拠: レーダー VH の湛水（その田でいちばん水の多い30日。4/20〜7/20）・春の裸地や水面（田起こし・代かき）・7〜9月の生育
    （晩生は 9/20 まで）・刈り取りの落ち込み（7/25〜10/25。ハナエチゼンの8月の刈り取り、刈り取り後の再生も数える）・
    麦の形（4〜5月に緑→6月前後に刈り取り。麦のあとに水を張った稲は麦にしない）・春から緑で耕起なし（草）・10月も緑で刈り取りなし
  - これらをデータの種類（レーダーの系列があるか・秋の観測があるか）ごとの小さなロジスティック回帰でまとめ、
    前後の年（輪作）と 150m 以内の田の傾向で少しだけ補正する（重みは学習済みで固定。実行時には学習しない）
  - 雲・かすみの落ち込み（2回続いても）と、レーダーの軌道ごとのずれを除いてから使う
  - 手で確かめた 461 件で、稲の見分けの F1 0.978（誤って稲 1件・見落とし 13件）。市町の統計（水稲作付面積）より 6〜12% 多めに出る（特に嶺南）。
    小さい田（10m 画素 3個未満）・水が見えない直播・雑草の多い稲は間違えやすい
  - 今年（収穫前）とデータが 10/20 まで届いていない年は「暫定」。入力が欠けた年は前回の見分けを残す（--prev）
  - crop_s.json がないセル・年は、地図の画面で簡単な決まり（4月の NDVI・7月の NDVI・5〜6月のレーダー・春の裸地・秋の刈り取り）で見分ける
  区画の縁（約8m）は畦・道路が混ざるので計算に使いません
- ハマりやすさ: 土壌図は 1/5万なので田の中の違いは分からない。SWIR は黒っぽい土（黒泥土・泥炭土）を湿って見せる（土と重なるが、どちらもハマる向き）。
  地下水位・暗渠・作土の下の硬盤（すき床）は見えない。最初の GEE の確かめは `python pipeline/wet.py --probe --cells <セルID>`（日ごとの使う・使わないと時間を出す）
